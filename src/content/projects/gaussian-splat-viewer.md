## 项目概览

这是一个运行在浏览器中的 3D Gaussian Splatting 场景查看器。项目使用 Spark 解析和渲染压缩后的 SPZ 数据，并通过 Three.js 管理相机、WebGL 上下文和交互控制，让访客无需安装桌面软件即可进入真实空间采集结果。

项目不只验证“能否把场景显示出来”，还重点处理了真实产品中更容易被忽略的问题：大体积数据何时加载、不同坐标系如何对齐、如何自动找到合理的初始视角、切换场景时怎样释放旧资源，以及复杂参数如何在不阻塞画面的前提下实时调节。

> 如果想先了解 3DGS 的表示方式、训练过程和渲染原理，可以阅读《[3D Gaussian Splatting 入门：原理、流程与应用](/writing/3d-gaussian-splatting-intro)》。

## 技术栈

| 模块       | 技术                           | 用途                                        |
| ---------- | ------------------------------ | ------------------------------------------- |
| 高斯渲染   | 3DGS、Spark                    | 加载 SPZ 数据，完成高斯排序、LoD 与实时绘制 |
| 场景基础   | Three.js、WebGL                | 管理渲染器、透视相机、场景图与颜色空间      |
| 交互       | OrbitControls、Keyboard Events | 环视、缩放、平移、自动旋转与六方向移动      |
| 页面集成   | Astro、TypeScript              | 静态页面、按需加载与页面生命周期管理        |
| 状态持久化 | Local Storage                  | 保存查看器的渲染参数和用户偏好              |

## 整体实现

查看器被拆分为展示层、场景控制器和参数面板三部分：

```text
Astro 体验页
  ├─ 用户点击“加载 3D 场景”
  ├─ 动态导入场景控制器与参数面板
  └─ GaussianSplatScene
       ├─ Three.js Renderer / Camera / OrbitControls
       ├─ SparkRenderer
       ├─ SplatMesh（SPZ）
       └─ GaussianSplatPanel
```

Astro 组件负责加载界面、进度反馈和按钮状态；`GaussianSplatScene` 负责 WebGL 场景、数据加载、相机和渲染循环；`GaussianSplatPanel` 只管理表单状态，再将变更以参数对象传给渲染层。这样可以避免界面事件和底层渲染 API 相互耦合，也便于继续增加新场景或新控制项。

## 场景加载与配置

### 点击后再加载

初始页面只渲染封面、说明和“加载 3D 场景”按钮。只有用户确认进入后，浏览器才会动态导入 Spark 查看器代码并下载 SPZ 文件。普通项目页因此不需要承担 3D 引擎和场景数据的网络、解析与 GPU 开销。

加载过程中，`SplatMesh` 的下载回调会根据已传输字节更新进度；当 `initialized` Promise 完成后，查看器才计算取景并进入渲染状态。网络失败或 WebGL 初始化失败会保留可重试的错误界面，而不会让整个页面失去响应。

### 数据驱动的多场景配置

场景 URL、文件大小提示、缩放、旋转、平移和默认相机都集中在独立配置中。增加一个新场景时，不需要改动渲染循环，只需补充一条配置。

不同采集工具可能使用 Y-up 或 Z-up 坐标系。项目通过四元数在加载阶段完成坐标转换，并把变换顺序统一为：

```text
scale → quaternion → 自动居中 → position
```

对于能够自动取景的场景，查看器读取高斯包围盒，计算场景中心和尺寸，再动态设置相机的 near、far、移动速度与缩放范围；特殊场景也可以直接提供调试后的相机位置和注视点。

### 场景切换与资源复用

切换场景时，旧的 `SplatMesh` 会先从场景图移除并释放 GPU 资源；Three.js 渲染器、相机、控制器和 SparkRenderer 则继续复用。这样既能避免高斯数据在显存中累积，也不会在每次切换时重建 WebGL 上下文。

## 渲染与交互

查看器使用高性能 WebGL 上下文，并按设备像素比和屏幕宽度限制渲染分辨率，避免在高 DPI 移动设备上产生不必要的像素开销。输出颜色空间设置为 sRGB，使采集场景的颜色在浏览器中保持一致。

交互层提供：

- 鼠标或触控拖动环视、滚轮缩放；
- `W / A / S / D` 水平移动，`Q / E` 上升和下降；
- 自动旋转、暂停旋转和恢复默认视角；
- 场景切换、全屏查看；
- 窗口尺寸变化时自动更新相机比例和渲染尺寸。

用户主动拖动或按下移动键后，自动旋转会立即停止，避免控制器与用户输入竞争。

## 实时参数面板

项目将 Spark 和 SplatMesh 中具有展示价值的参数整理成可视化控制面板，包括：

- 高斯不透明度、统一染色和球谐阶数；
- 高斯延展、锐度、衰减、Alpha 截断和像素半径；
- 径向排序、2D Gaussian 模式与预模糊；
- LoD 细节倍率与最小绘制尺寸；
- 景深、焦距、光圈和注视点渲染范围。

修改球谐、LoD、景深或注视点参数可能触发数据生成、排序或 LoD 重算。面板会对这些高开销更新单独进行 debounce，避免拖动滑块时每一帧都重建数据。参数同时写入 Local Storage，再次进入页面时可以恢复上次的观察设置。

## 性能与生命周期

为了让 WebGL 实验能够安全地存在于 Astro 网站中，项目补充了完整的生命周期处理：

- 查看器和 SPZ 数据只在用户点击后加载；
- 设备像素比设有上限，控制移动端填充率；
- `ResizeObserver` 只监听体验容器，而不是持续轮询窗口；
- 场景切换时释放旧高斯对象；
- 离开页面前取消动画帧和键盘事件；
- 释放 OrbitControls、SplatMesh、SparkRenderer 与 WebGLRenderer；
- 清空场景图，避免 Astro 页面切换后仍保留 GPU 上下文。

这部分使体验页可以与普通文章和项目页面共存，而不会在访客离开后继续占用 CPU、音频或显存。

## 实现难点

### 初始视角不稳定

不同 SPZ 文件的尺寸、原点和坐标系并不统一。固定相机参数只能适配一个场景。项目最终使用“配置变换 + 包围盒自动取景”的组合：通用场景自动计算，少数构图要求明确的场景覆盖相机位置。

### 参数调节造成卡顿

部分参数不是简单修改 uniform，而会标记排序、LoD 或生成器为 dirty。项目把轻量更新与高开销更新分开调度，对后者增加延迟合并，保证连续拖动时仍能保持可交互。

### 单页导航后的资源残留

Astro 的视图切换不会像完整刷新那样自动销毁 WebGL 对象。项目监听页面切换事件，在离场前主动执行统一的 `destroy()`，确保事件、动画循环和 GPU 资源成对创建、成对释放。

## 当前结果与后续方向

目前查看器已经支持多个 SPZ 场景、自动与手动取景、六方向移动、完整参数调节和跨页面资源回收。它证明了压缩高斯场景可以作为独立体验稳定集成到内容型静态网站中。

后续可以继续加入场景缩略图、加载质量档位、移动端简化模式、性能统计，以及基于相机距离的更精细 LoD 策略。
